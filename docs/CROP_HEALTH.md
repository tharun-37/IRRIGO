# Crop Health Assistant — status and contract

The image-based crop health assistant is being built against the blueprint's
sub-system definitions. This page is the single source of truth for what is
**implemented**, **under test**, **proposed** and **pending**, and it is
deliberately free of accuracy claims.

## API

### `POST /api/crop-health/analyze` (multipart)

| Field | Required | Notes |
|---|---|---|
| `file` | yes | JPEG/PNG/WebP ≤ 10 MB, decode-limited |
| `crop` | yes | free text today; checked against a deployed model's `crops` list once one exists |
| `plant_part`, `growth_stage`, `field_id`, `zone_id` | optional | recorded as farmer context |
| `consent` | optional flag | **without consent the photo is analysed and immediately deleted — nothing is retained** |

Response carries: `analysisId`, `createdAt`, `crop`, `resultStatus`,
`statusReason`, `prediction` (`task`, `classLabel`, `rawScore`, `calibrated`,
`supportedClasses`), `advice` (`adviceCode`, `adviceText`, `textVersion`,
`followUpQuestion`, `expertReferral`), `quality` + `gates`,
`modelVersion`/`preprocessingVersion`, `validationStatus`, `imageReference`
(a controlled-storage key, never a public URL).

### Result statuses

`result` — a deployed, supported class came back (requires a validated artifact).
`uncertain` — photo passed but the model is absent or below the abstention
threshold. `unsupported_crop` — the deployed model does not cover the crop.
`poor_image` — blurry, dark, bright or flat photo; no diagnosis attempted.
`invalid_input` — unreadable/oversized/mismatched upload. `processing_error` —
something the service broke on.

## Privacy and security (implemented)

- Uploads live under `backend/data/crop_health/images`, addressed by random
  content keys; the DB stores references, never blobs and never URLs.
- EXIF (including location) is stripped on capture; only re-encoded pixels are stored.
- Consent is explicit: `consent: false` means analyse-and-delete.
- `DELETE /api/crop-health/analyses/{id}` removes record **and** file.
- The API has no authentication yet and is **not** safe to expose beyond a
  trusted local network — that work is a stated precondition to any field pilot.

## Fertilizer recommendation layer

Deliberately separate from the nutrient-prediction ML. It recomputes nothing:
`POST /api/fertilizer/recommend` takes crop, growth stage, field area + unit,
an optional soil test (with units and source) and an optional product
formulation, and returns per-nutrient targets/supply/deficit in **kg/ha and
kg for the stated field**, with the derivation, assumptions, missing inputs and
reminders attached.

Rules it never breaks: missing soil test → no product mass (`needs_soil_test`);
missing or non-matching formulation → no product mass (`missing_product`);
absent soil values are never read as zero; area-based and total-field
quantities are never mixed in one displayed number.

Tests: `backend/tests/test_fertilizer.py` covers area conversion, nutrient
percentages, missing values, rounding and split logic.

## Dataset manifest

`POST`-free viewer: `GET /api/crop-health/manifest` serves
`backend/ml/crop_health/manifest.json` (generated by `build_manifest.py`).
It records: every tabular dataset with sha256 + row/column profile; the
pending image collections; the split rules (group by plant/farm/session;
independent held-out field-photo test set); and the honest current status of
the image model work.

## Known limitations (as deployed today)

1. No disease, pest or nutrient image model exists. Every analysis returns
   `uncertain` with an explicit "no validated model is deployed" reason once
   photo quality passes.
2. Quality-gate thresholds are hand-set against demo phones, not validated on
   a labelled poor-image set — the `poor_image` classification itself is
   "under test".
3. Colour fractions (green/yellow/dark) are recorded for future model
   features; nothing in the UI treats them as findings.
4. Advice text never names a pesticide, never recommends a dose from a photo,
   and routes suspicious/spreading problems to an agricultural officer.
